# 分级多代理任务树交接手册

完整规则源为 [AGENTS.example.md](AGENTS.example.md)，安装器与 MCP 初始化都读取它。此手册解释流程，不建立另一套独立状态。所有示例身份、命令结果和指纹都是占位说明，不能当作真实验收。

## 安装必须同时包含规则

源码目录执行 `npm run setup -- --apply --codex-metadata`，随后 `npm run doctor`。`--apply` 明确允许安全合并全局配置和规则，默认 setup 仅预览。元数据开关明确选择本机归档/项目只读同步，不需要时可省略。支持 `--codex-home` 隔离配置目录；普通用户不要每个对话设置独立服务状态目录。

doctor 通过后重新加载 MCP 客户端并开始新的 Codex 运行，再实际演练创建计划、打开当前对话页面及验收。MCP 初始化返回规则不是全局文件已安装的证据，旧对话不保证热加载。全局覆盖文件会导致安装失败，项目级覆盖需另外核对。

## 先计划再执行

大型实现前先核对目标和适用规则，读取真实 `CODEX_THREAD_ID`，以稳定 `board_id` 创建 4~8 个主阶段，复杂阶段继续递归拆解。用 `console_list` 确认本对话已登记，再实现。不同目标用不同工作项，同目标排障、修复和验收仍放在原树。已有专用任务文件可用 `console_watch`，不要维护两份会漂移的计划。

首次执行用 `console_open` 取得本对话 URL，宿主提供侧边浏览器工具时在当前对话右侧打开，否则提供普通浏览器链接。只打开网址没有登记任务；点击历史对话也不存在本工具注入的原生打开钩子。MCP 不可用时用 `node bin/cli.mjs` 的 plan/update/add/move/rename/watch/list，指定真实对话 ID；所有通道失败则明确保留未同步的本对话任务文件，不伪称同步完成。

## 每一级只管理直接子节点

```text
总控：owned_parent=null，只管理主阶段
  主阶段负责人：管理本阶段的直接子阶段
    子阶段负责人：管理下方的实现、自测、独立复核和父级验收节点
```

负责人不能自行接受自己的 `owned_parent`，也不能代改更深后代或兄弟阶段。自己下方完成后提交报告，由上一级核对差异、审查结果与实际验证，再接受该父阶段。模型自动汇总和重开祖先不算代理越级，人工写祖先状态/证据仍须逐级交接。

当前每个工作项只允许一个显式执行中的叶子，实现、自测、独立审查、父级验收必须串行交接；同文件只有一个实现者。总控调度实际可用槽位，活跃代理含总控最多 4 个，逻辑深度默认最多 3 层，不为每个琐碎动作创建代理，也不新建工作项绕过串行限制。

## 委派与交接格式

每次委派明确目标、输入、依赖、验收条件、允许修改的准确文件、禁止操作与结果格式，并携带：

```json
{
  "thread_id": "<当前真实对话ID>",
  "board_id": "<稳定工作项ID>",
  "step_id": "<获分配阶段ID>",
  "owner_agent_id": "<实际代理标识>",
  "tree_owner": "<本层负责人标识>",
  "owned_parent": "<管理的父节点ID，顶层才是null>",
  "writable_child_ids": ["<获准直接管理的子节点ID>"],
  "files": [{"path":"<文件>","sha256":"<实际字节指纹>"}],
  "input_fingerprint": "<实际输入与验收条件指纹>",
  "verification": [{"command":"<实际命令>","cwd":"<实际目录>","exit_code":0,"result":"<关键结果>"}],
  "unfinished": ["<未完成和未验证项>"],
  "risks": ["<剩余风险>"],
  "suggested_tree_changes": ["<建议动态调整及理由>"]
}
```

独立审查由未实现该批变更的另一代理执行，另附 `reviewer_agent_id`、`reviewed_fingerprint`、`decision=pass/rework/blocked`、问题位置及自己实际复跑结果。实现者自测不是独立审查，代理返回不是任务验收。这些字段是交接合同，不是 MCP 工具额外参数或服务端权限凭证。

每个父负责人只把交接摘要和真实标识写到自己直接管理节点的 evidence；必要完整记录放在项目现有 `_ai/` 或文档化诊断位置，不存秘密、不直接写 state/、不另建漂移看板。代理运行标识不能替换原工作项对话 ID。

## 动态调整与审查退回

- 粒度过大时保留原节点作父阶段，添加具体子阶段；可 move/rename。原方案失效才 skipped 并说明原因，保留历史，不先废弃父节点再往它下面加孩子。
- 跨父移动要双方负责人同意，相关执行者停止写入后记录旧/新 owner 与范围，并更新 writable_child_ids。不能靠结构调整越级写入。
- 审查发现问题由该叶子的直接父负责人设 blocked，原实现负责人重开实现或添加修复，再提交新指纹。模型会重开祖先，但不会自动重开已完成的审查/验收兄弟；各级负责人必须显式重开自己的受影响节点，通过父链协调其他层级。
- 修复后必须对新指纹重审，不能复用旧 pass。两轮修复仍失败时停止机械重试，记录阻碍、调整相关子树，只重试最小失败范围。扩大授权、范围或显著成本前交用户决定。

## 逐层验收与恢复

代码修改实际运行适用测试、lint、类型检查或构建并取得退出码 0；浏览器任务核对真实数据、状态或截图/网络证据。失败、环境不具备或遗留必要缺陷不能 done。叶子要真实 evidence，父节点在所有有效子节点通过后还必须补自己的验证。废弃不能静默免除产品验收，翻译也不是新验收。

本级仅接受直接管理的验收叶子，提交报告给上级；上级完成自己的核验再接受子交付父节点，依此递归。最终交付列出实际完成与验证结果、动态调整/废弃及原因、修改文件与明确限制。

中断或上下文压缩后先读已有树、实际代理存活状态、当前差异、最后指纹及管理权。未确认原执行者停止不能换人写同文件；接管需上级明确移交，不抢占树管理权或重建看板掩盖失败。代理不可用可明确降级，但不能伪造独立审查。所有委派不能扩大提交、发布、外部通信、提权、删除等用户授权。

## 共享服务与真实边界

所有普通对话共享一套本机服务和状态，以真实 thread_id 隔离。其他看板打开时不停止服务；最后一个实际连接断开且 60 秒没有任务查询/写入时释放端口、轮询、计时器和锁，下次 CLI/MCP 恢复历史。直接访问已退出网页不能唤醒进程。维护者修改资源后停服务/重开/刷新一次，普通任务不重复重启。

原生元数据只读同步为明确 opt-in，受版本影响；归档隐藏不删除历史，取消归档恢复。读取失败保留最后有效数据并警告。关闭选项时不能假称具有原生归档能力。工作项按进行中、阻塞、待验收、待办、已完成、已废弃排序，同组最近更新优先。

当前没有生产 actor ACL，分级边界是行为规范，不是硬权限隔离。MCP 不能独立证明 evidence 中的命令执行过；doctor 不能证明项目覆盖、全部合并指令容量、未来模型遵守、旧对话热加载或侧栏能力。任意客户端/模型完全同效果、零缺陷不是可兑现的保证。公开内容只含通用流程，不能发布个人路径、配置、凭据、聊天、任务历史或真实截图。
